# 校园报修管理系统需求规格说明书

## 1. 系统概述

### 1.1 定位与目标
- **系统定位**：本系统是一套面向高校全场景的综合设施运维与报修服务管理平台，涵盖学生宿舍生活区、教学科研区及公共区域的设施设备报修与维保管理。
- **建设目标**：
  - 打造标准化、工程级闭环的报修全生命周期管控流程（提单-派单-维修-验收-评价-返工）。
  - 实现基于「区域空间 + 维修工种 + 实时负荷均衡」的智能自动派单，辅以后勤管理员灵活人工调度干预机制。
  - 引入轻量级耗材备件进销存体系，精确核算单次维修成本并实现库存安全预警。
  - 构建全链路质量监督机制（超时自动核销、多维服务评分、差评标红预警与二次返工督办）。
  - 搭建后勤运营指挥大屏，全景可视化呈现校园设备健康度、维修效率与师傅绩效。

### 1.2 目标用户与角色
系统采用职责解耦清晰的**四角色架构**：
1. **报修师生（学生/教职工）**：
   - 权限与诉求：便捷提交报修单（空间联动定位、多图凭证、预约时段），实时追踪工单进度时间轴，确认完工效果并进行满意度打分评价；维护个人资料与默认报修地址。
2. **维修师傅（一线作业人员）**：
   - 权限与诉求：使用移动端自适应工作台接单、查看报修详情并一键电话外呼联络、执行上门维修；支持物料短缺或外部协调时的「工单挂起」与「申请转派」；完工时上传现场对比照片并核销所消耗备件。
3. **后勤管理员（调度中心与质量监督员）**：
   - 权限与诉求：全局监控工单流转状态；对自动派单失败或师傅申请转派的工单进行人工调度；处理报修人差评与验收不合格工单（仲裁督办、重新派单）；管理备件耗材采购入库与安全库存；查看运营指挥大屏与导出报表。
4. **系统管理员（平台运维人员）**：
   - 权限与诉求：维护系统基础底座，包括空间网格层级（校区/楼栋/房间）、故障大类与工种字典、用户账号体系（批量导入、权限授权分配）以及系统审计日志与运行参数。

### 1.3 核心使用场景
- **场景一：师生移动便捷报修**
  师生发现宿舍空调制冷失效或公共教室投影仪异常，掏出手机进入系统，通过空间联动选择具体楼栋房间，勾选两级分类并上传现场损坏照片，选择期望上门预约时段，提交生成报修单。
- **场景二：规则自动分派与负荷均衡**
  系统根据工单所属区域（如西区学生公寓）及故障所属工种（如家电制冷），在空闲师傅中自动匹配当前未完成工单数最少的人员进行即时指派；若对应工种全员满载或无匹配人员，则自动流入调度池提醒管理员人工分派。
- **场景三：一线师傅现场移动作业**
  师傅收到站内即时派单提醒，在手机工作台点击接单前往现场。维修过程中若遇特殊零部件缺失，可发起「挂起待料」说明原因；修复完成后，在现场拍摄完工成果照，勾选领用的配件耗材（如更换电容1个），提交完工结单。
- **场景四：超时验收与差评返工仲裁**
  师生验收通过后进行评分。若师生在72小时内未手动验收，系统触发自动验收确认。若师生打出≤2星差评并注明「未彻底修好」，系统立即触发异常预警标红，后勤主管介入核实，将工单定性为「返工待派」并指派资深师傅返工修复，形成业务闭环。
- **场景五：后勤物资管理与大屏指挥**
  后勤主管定期登记耗材采购入库，系统根据师傅维修出库自动扣减。当水龙头等耗材降至安全库存阈值以下时，系统标红预警并一键生成采购清单。主管通过数据大屏实时监控全校各区域故障高发趋势及师傅接单效率排行。

## 3. 用户与认证子系统 (User & Auth Subsystem)

### 3.1 用户登录与安全认证模块
- **功能说明**：提供统一安全凭据校验通道，支持全系统四类角色的身份鉴权。
- **涉及元素**：
  - **登录凭证校验**：支持学号/工号/手机号作为登录主体识别符，校验加密密码。
  - **图形验证码防刷**：登录界面集成轻量动态验证码，连续输错3次强制输入验证码校验。
  - **会话鉴权令牌**：无状态双令牌（访问Token + 刷新Token）机制，保障移动端与PC端安全鉴权。
  - **初始密码强制变更**：初次由管理员导入的账号，首次登录强制弹出安全提示修改初始弱密码。

### 3.2 师生自主注册与资料维护模块
- **功能说明**：允许在校学生与教职工通过移动端或PC端自助激活账号，绑定基础信息。
- **涉及元素**：
  - **注册表单字段**：真实姓名、学号/工号（唯一性校验）、联系手机号、所属学院/部门、默认物理住址（校区-楼栋-房间级联）。
  - **手机号格式与唯一性规则**：校验11位大陆合法手机号格式，数据库唯一索引防重。
  - **个人中心资料卡**：支持自主修改联系电话、常用报修住址、修改个人登录密码、查看个人报修历史汇总统览。

### 3.3 账号管理与批量导入模块
- **功能说明**：供系统管理员维护全校人员台账，重点支持新学期大批量人员初始化。
- **涉及元素**：
  - **单条增删改查**：管理员可手动创建师生、维修师傅、后勤管理员账号，设置工号、初始密码、启用/禁用状态。
  - **Excel模板批量导入**：
    - 提供标准Excel模板下载（含学号、姓名、手机号、角色类型、班组/工种）。
    - 导入解析与前端实时校验，展示导入成功数、失败行号与失败原因（如学号重复、手机格式错误）。
  - **密码重置操作**：支持管理员一键将指定用户密码重置为系统预设安全初始密码。

### 3.4 角色与数据权限配置模块
- **功能说明**：构建基于RBAC的角色权限访问控制机制，实现页面级菜单与操作按钮权限隔离。
- **涉及元素**：
  - **四角色内置模板**：预设系统管理员（SuperAdmin）、后勤管理员（LogisticsAdmin）、维修师傅（RepairWorker）、报修师生（UserStudent/UserTeacher）。
  - **菜单与按钮鉴权控制**：移动端只呈现师傅工作台与师生端报修中心；PC管理端按角色细分大屏看板、调度中心、耗材管理与系统设置。

## 4. 空间与业务字典子系统 (Spatial & Dictionary Subsystem)

### 4.1 校园空间层级管理模块
- **功能说明**：构建四级树状物理网格空间体系，支撑提单时的精确定位与网格化派单。
- **涉及元素**：
  - **四级空间层级树**：校区（如朝阳校区/海淀校区） -> 区域组团（如学生公寓北区/基础教学区） -> 楼栋（如1号学生公寓/第三教学楼） -> 楼层与房间（如302宿舍/101多媒体阶梯教室）。
  - **空间属性配置**：支持维护楼栋性质（学生宿舍、教工住宅、教学办公、公共场馆、室外绿化）。
  - **楼栋负责人绑定**：支持在楼栋节点绑定预设网格管理员或默认维修责任人。
  - **状态启用控制**：支持停用正在修缮或已拆除的楼栋空间，停用后师生提单无法检索该节点。

### 4.2 故障分类与工种映射模块
- **功能说明**：维护故障两级分类，并建立故障类型与维修师傅工种专业技能的映射字典。
- **涉及元素**：
  - **故障两级树状字典**：
    - 一级大类（如水电设施、房屋土建、暖通空调、多媒体设备、门窗家具、公共照明）。
    - 二级细类（如水电大类下的：水龙头漏水、马桶冲水失灵、插座断电、管道爆裂等）。
  - **所属专业工种绑定**：每个二级细类绑定标准工种标识（如水暖工、高低压电工、锁匠木工、空调制冷工、网络多媒体工程师）。
  - **标准时限（SLA）配置**：配置每个故障细类的预估解决时限（如普通水暖24小时、紧急管道爆裂2小时），超时自动标黄预警。

### 4.3 业务参数与规则配置模块
- **功能说明**：配置全局自动化调度阈值与超时核销规则。
- **涉及元素**：
  - **自动验收超时周期**：默认配置为72小时（可调范围24~168小时）。
  - **差评警戒阈值**：星级≤2星自动触发质量督办工单。
  - **师傅最大承单负载上限**：配置单个师傅未完结工单并发上限（如默认上限10单，达上限后自动派单不再分配该师傅）。

## 5. 工单全生命周期子系统 (Work Order Subsystem)

### 5.1 师生报修提单模块
- **功能说明**：报修人在移动端或PC端填写故障详情，建立报修单据。
- **涉及元素**：
  - **工单唯一编码规则**：生成全局唯一业务编号（规则：`BX` + 年月日8位 + 6位递增序列流水号，如 `BX20260906000001`）。
  - **提单表单核心要素**：
    - 故障分类（大类-细类两级级联下拉选择）。
    - 故障空间位置（校区-楼栋-房间三级联动，支持调取常用历史默认地址）。
    - 详细描述（必填多行文本输入框，限制10~500字）。
    - 现场照片上传（支持1~3张图片拍照或本地选取，限制图片单张最大5MB，前端压缩）。
    - 紧急程度标识（普通日常、加急紧急）。
    - 期望上门预约时段（预设枚举：工作日上午08:30-11:30、工作日下午14:00-17:30、夜间时段18:30-21:00、周末全天）。
    - 联系电话（默认带出个人信息手机号，允许手动临时修改）。
  - **提单防重校验**：同一空间节点在未结单情况下提交相同故障小类，前端弹出「该位置存在未处理报修」温和提醒，避免并发重复提单。

### 5.2 智能规则自动派单模块
- **功能说明**：工单提交后瞬间触发后台自动化分配调度算法。
- **涉及元素**：
  - **调度触发器**：新工单落库后立即由异步调度引擎接管。
  - **匹配与过滤逻辑**：
    1. 工种匹配：根据故障细类绑定的专业工种，过滤出具备该技能证书/标签的师傅池。
    2. 区域匹配：筛选负责该工单所在校区或楼栋组团的师傅列表。
    3. 状态校验：校验师傅在岗状态（非请假、非离线）。
    4. 负荷均衡评分：计算符合条件师傅的「当前处理中工单数量」，选取工单积压量最少、且未达到个人负载上限的师傅作为最优指派对象。
  - **降级与兜底机制**：若无匹配师傅或所有师傅均达负载上限，工单状态流转为「待人工调度」，并推送到后勤调度中心待办顶层。

### 5.3 调度中心人工派单与干预模块
- **功能说明**：后勤管理员专属控制台，支持对全校工单进行人工调度、改派、催办与仲裁。
- **涉及元素**：
  - **待办工单调度池**：列表展示所有自动派单失败、师傅申请转派、以及加急异常工单。
  - **人工指派/改派操作**：管理员选择指定师傅弹窗，直观展示每位师傅的工种、今日已完成单数、当前在修负荷量，支持一键指派。
  - **催办督办标记**：针对超时未处理工单，管理员点击「一键催办」，向对应师傅发送高优先级待办通知。
  - **废单与取消处理**：经与报修人核实为误报或恶作剧报修，管理员具备权限填写取消原因并作废单据，通知报修人。

### 5.4 维修师傅移动作业台模块
- **功能说明**：维修师傅在移动自适应Web端执行工单承接与完工上报操作。
- **涉及元素**：
  - **移动看板三栏卡片流**：
    - 「待承接」：展示刚指派过来的新工单列表，高亮预约上门时段与紧急程度。
    - 「维修中」：展示已接单、正在排期或现场维修的工单。
    - 「历史记录」：展示已完成和已评价的归档工单。
  - **一键快捷外呼**：工单详情卡片集成 `tel:` 唤起拨打电话协议，师傅点击按钮直接拨打报修师生电话沟通上门时间。
  - **开始维修（接单）动作**：点击「接单出发」，工单状态变更为「维修中」，记录接单时间戳。
  - **完工填报核心要素**：
    - 维修处理总结（文本输入：说明故障根因与排除手段）。
    - 现场修复对比照（强制要求上传1~3张修复后照片）。
    - 耗材核销填报（支持多选系统备件库，录入消耗件数，如：三角阀1个、生料带1卷）。

### 5.5 异常挂起与转派申请模块
- **功能说明**：保障一线遇到突发困难时流程不中断、责任不断档。
- **涉及元素**：
  - **工单挂起操作**：
    - 适用条件：现场缺专用大件备件、需要校外厂家维保介入、或现场断电停水无法施工。
    - 填写要素：挂起原因分类选择、详细原因描述、预计恢复时间。
    - 流转状态：工单变为「已挂起」，暂停SLA超时倒计时计算，并向报修师生发送挂起进度解释通知。
  - **解除挂起动作**：物料到位后师傅点击「解除挂起恢复施工」，重置状态为「维修中」。
  - **申请转派操作**：
    - 适用条件：现场判定实际故障超出自身工种领域（如修水龙头发现墙体内部强电打火）。
    - 填报要素：转派原因分类、推荐转移工种或指定推荐师傅。
    - 流转状态：提交后直接移交后勤调度中心，原师傅移出工单责任链。

### 5.6 完工验收、评价与差评返工模块
- **功能说明**：驱动质量验收闭环，针对维修质量实施动态奖惩监督。
- **涉及元素**：
  - **报修人确认验收**：师傅完工后，工单变为「待验收」，报修人端呈现修复照片对比卡片，可点击「确认完工并评价」。
  - **72小时超时自动确认**：工单达到「待验收」状态起，倒计时72小时整，若报修人未手动确认，系统后台定时任务自动将状态变更为「已结单（系统自动验收）」。
  - **服务评价指标要素**：
    - 综合满意度星级（1~5星单选打分）。
    - 服务标签快速勾选（如：技术专业、态度极佳、上门迅速、着装规范、现场清理干净）。
    - 详细评语文字（选填，限制0~200字）。
  - **差评自动标红与返工督办机制**：
    - 判定条件：综合星级≤2星，或报修人主动拒绝验收标记「维修不合格」。
    - 系统动作：工单状态立即流转为「返工待派」，在后勤调度端大屏及待办列表红字高亮置顶。
    - 管理员仲裁决策：后勤主管电话回访报修人后，可在后台选择「退回原师傅限期整改」或「换派高级技师重新处理」。
    - 审计全景树：工单流转日志保留原始维修记录与二次返工全过程，作为师傅月度绩效扣分考核依据。

## 6. 备件耗材轻量进销存子系统 (Spare Parts & Inventory Subsystem)

### 6.1 耗材备件台账维护模块
- **功能说明**：管理维修日常所需的五金、水电、建筑耗材的基础字典与属性信息。
- **涉及元素**：
  - **耗材台账字段**：备件物料编号、名称（如PPR冷水弯头20mm、LED吸顶灯驱动器）、规格型号、计量单位（个/米/套/卷）、采购参考指导单价、当前实际库存数量、安全库存阈值报警线。
  - **状态管控**：支持备件上架/停用，停用后师傅端完工核销无法选配。

### 6.2 采购入库流水管理模块
- **功能说明**：记录后勤库房日常采购批次与数量入库登记，确保账实相符。
- **涉及元素**：
  - **入库单据字段**：入库流水号、采购批次时间、关联备件选择、入库数量、实付单价、经办采购人、入库备注。
  - **库存累加业务规则**：单据提交确认后，底层实时对主台账当前库存进行事务累加，并生成一条不可篡改的入库审计流水日志。

### 6.3 维修核销与自动出库模块
- **功能说明**：将维修作业与库房消耗紧密绑定，杜绝耗材虚报流失。
- **涉及元素**：
  - **工单核销明细**：关联工单编号、维修师傅姓名、消耗物料ID、消耗数量、核销时间。
  - **库存自动扣减规则**：师傅完工提交时，系统对关联物料执行出库扣减校验；若当前库存量小于师傅报送数量，提示师傅核实或允许负库存预警登记。
  - **工单维修成本自动核算**：根据「消耗数量 × 物料指导单价」自动汇总计算出单张工单的直接耗材费用，供后续成本核算。

### 6.4 安全库存预警与补货模块
- **功能说明**：防止一线因常用零部件断货导致工单大面积挂起停滞。
- **涉及元素**：
  - **动态低库存红字报警**：当 `当前实际库存 <= 安全库存阈值` 时，台账界面自动变红，工作台顶部弹出库存预警横幅。
  - **一键导出待采购补货清单**：系统支持一键筛出所有处于欠缺状态的耗材，导出Excel采购建议单（包含缺口数量建议）。

## 7. 消息中心与通知调度子系统 (Notification Subsystem)

### 7.1 站内消息与待办提醒模块
- **功能说明**：全端统一的站内通知中心，消除信息不对称。
- **涉及元素**：
  - **消息分类机制**：
    - 工单业务提醒（派单成功、师傅已接单上门、完工待验收、评价提醒）。
    - 调度与运维督办（超时催办、差评返工通知、安全库存告警）。
    - 后勤广播公告（如全校水管阀门例行维保停水通知）。
  - **界面交互元素**：右上角铃铛小红点提示、未读消息计数徽标、一键全部标记为已读、消息点击直达工单详情。

### 7.2 状态流转时间轴追溯模块
- **功能说明**：在工单详情页提供类似物流追踪的时间轴视图，全透明展示处理链路。
- **涉及元素**：
  - **时间轴节点要素**：发生时间、操作主体（报修人/系统调度器/张师傅/管理员）、流转动作（提交报修 -> 智能派单 -> 师傅接单 -> 挂起说明 -> 恢复施工 -> 完工上传 -> 验收通过 -> 5星好评）、详细图文备注展示。
  - **审计追溯不可逆**：所有状态变更历史由独立流转日志表固化存储，任何角色无法篡改历史节点数据。

### 7.3 外部通知适配抽象模块
- **功能说明**：设计松耦合的消息发送抽象层，兼顾毕设运行演示便利性与真实系统可扩展性。
- **涉及元素**：
  - **通知接口适配器**：支持配置驱动模式（可一键切换为 `MockConsoleNotifier` 控制台输出模式、`MailNotifier` 邮件发送模式、或商业短信服务接口）。
  - **本地开发无缝体验**：默认启用本地日志与Mock打印模式，在IDEA控制台直接打印包含验证码或工单变动的模拟通知内容，无需申请收费第三方通道。

## 8. 统计分析与运营看板子系统 (Dashboard & Analytics Subsystem)

### 8.1 后勤运营指挥大屏模块
- **功能说明**：后勤管理层专属视觉指挥中心，集成核心KPI看板与可视化图表。
- **涉及元素**：
  - **顶部核心指标KPI卡片**：
    - 历史累计报修总量。
    - 今日新增报修单量。
    - 当前处理中工单数（包含在修与挂起）。
    - 全校维修完工闭环率（百分比）。
    - 平均修复响应时长（从提交到完工的平均小时数）。
    - 师生综合服务满意度指数（如 4.88 / 5.0 分）。
  - **近30天报修与修复趋势图**：双折线/面积图，展示每日报修量与每日结单量对比趋势，观察后勤负荷波动。
  - **校园空间故障热力/柱状图**：按校区和楼栋分布，直观展现报修高发频次的宿舍楼与教学楼分布。
  - **故障类型结构占比饼图/环形图**：水电类、暖通类、多媒体类等类别的占比分析，指导后勤工种招聘与排班。
  - **维修师傅绩效排行榜Top榜**：师傅完工量柱状图、平均处理时效榜、好评率红黑榜。

### 8.2 工单多维高级检索模块
- **功能说明**：提供强大的列表检索能力，满足管理人员日常精确定位与批量排查。
- **涉及元素**：
  - **多条件组合筛选面板**：
    - 关键词检索：模糊匹配工单号、报修人姓名、手机号、故障说明。
    - 空间层级联动筛选：按校区、楼栋、房间范围收窄。
    - 业务维度筛选：故障一级大类、二级细类、指定维修师傅、紧急程度。
    - 状态筛选：全部、待派单、待接单、维修中、已挂起、待验收、返工待派、已完结。
    - 时间跨度选择器：按报修提交日期范围、完工日期范围过滤。
  - **分页与排序控件**：支持按提交时间、紧急程度降序排序，每页展示条数自适应切换。

### 8.3 报表统计与数据导出归档模块
- **功能说明**：支持后勤例行周报月报数据生成与历史工单冷数据维护。
- **涉及元素**：
  - **一键Excel数据导出**：将当前多维高级检索得到的数据集完整导出为标准Excel文件，字段包含工单号、报修人、联系电话、空间位置、故障类别、负责师傅、提单时间、结单时间、消耗耗材与费用、满意度星级。
  - **历史办结工单归档标记**：支持对办结时间超过180天或1年的静态冷工单打上「已归档」标志，只读不可编辑，优化日常业务检索查询性能。

## 9. 业务流转状态机模型

系统工单生命周期的核心状态与迁移规则定义如下：

```text
[初始草稿]
    │
    ▼ (师生提交报修)
[待派单 (PENDING_DISPATCH)]
    │
    ├── (智能匹配成功) ───────────┐
    │                            ▼
    └── (匹配失败/超负荷) ──> [待人工调度 (MANUAL_DISPATCH)]
                                 │
                                 ▼ (管理员人工指派)
                           [待承接 (ASSIGNED)]
                                 │
                                 ▼ (师傅点击接单)
                           [维修中 (IN_PROGRESS)] ◄─────────────┐
                                 │       ▲                      │
              (遇到缺料/外部阻滞) │       │ (物料到位解除挂起)     │ (管理员仲裁返工)
                                 ▼       │                      │
                           [已挂起 (SUSPENDED)]                 │
                                 │                              │
                                 ▼ (师傅完工上传凭证)            │
                           [待验收 (PENDING_ACCEPTANCE)]        │
                                 │                              │
                     ┌───────────┴───────────┐                  │
                     ▼ (72h超时/主动满意评价)   ▼ (评价≤2星/不合格)     │
           [已结单 (COMPLETED)]        [返工待派 (REWORK_PENDING)] ─┘
```

## 10. 待确认与后续演进事项
1. **统一身份认证（CAS / OAuth2）对接**：当前设计采用系统自建用户表与自主注册模式，后续若部署于高校内网，需评估是否预留与高校智慧校园统一数字身份认证中心（LDAP / CAS）的接口对接。
2. **移动端终端演进形态**：当前设计为极佳性价比的 Vue 响应式移动端 H5 架构；未来可根据学校运维需求平滑包装为微信小程序端（借助 uni-app 架构或纯 Webview）。
3. **现场签到真实性防作弊机制**：当前主要依靠维修前后的两张现场对比照片与报修人验收作为核验凭证；后续是否需增加师傅手机 GPS 地理位置打卡距离校验（如偏差不能超过楼栋方圆200米）。
